# 手机包装专用检测模型 — 标注数据集方案

> 目标：训练一个只认「手机 / 手机盒上盖 / 手机盒下盖 / 说明书 / 充电器 / 充电线」6 类的目标检测模型，
> 导出 ONNX 后替换 `sop_*.yaml` 里的 `model.path`，让 `object_present` / `hand_near_object` 条件能命中真实物料。
> 现状痛点：系统现在用的是 COCO 通用 `yolov8s.onnx`，认不出手机盒、配件这些专属形态，必须换专用模型。

---

## 1. 类别定义（6 类，命名固定）

| id | 英文名（必须与 YAML `classes` 一致） | 中文 | 说明 | 易混淆点 |
|----|------|------|------|----------|
| 0 | `phone` | 手机 | 裸机或已入半盒的手机 | 与背景深色物、遥控器易混 |
| 1 | `case_top` | 手机盒上盖 | 翻盖式上盖（空） | 与 `case_bottom` 形状几乎一样，靠**摆放朝向 / 是否含物料**区分 |
| 2 | `case_bottom` | 手机盒下盖 | 装手机/配件的底座 | 同上 |
| 3 | `manual` | 说明书 | 折叠纸页 | 与桌面纸张、泡沫垫易混 |
| 4 | `charger` | 充电器 | 充电头方块（带插脚） | 与小纸盒、固定块易混 |
| 5 | `cable` | 充电线 | 细长线材 | **小物体难点**，易漏检；与绳子/标签带易混 |

> 关键提醒：`case_top` 和 `case_bottom` 外观高度相似，采集时务必让两者在画面里呈现**可区分的姿态**（例如上盖常斜放、下盖常正放且内有凹槽），并在标注时严格按实际角色打标，否则模型会学混。

---

## 2. 数据采集方案

### 2.1 机位与场景（优先级最高）
- **固定相机**：用部署时的同一台相机、同一安装高度/角度（建议俯视 30°~60°），不要手持随便拍。
- **光照一致**：与推理现场同光源。训练/推理光照分布偏移是现场 mAP 暴跌的头号原因。
- **分辨率**：相机输出 ≥ 1280×720；推理 ONNX 用 `imgsz=640`（YOLO 会自动 resize，不影响标注）。

### 2.2 数量建议
| 阶段 | 每类张数 | 总计 | 预期 mAP50 |
|------|----------|------|------------|
| MVP 初版 | 100~150 | 600~900 | 0.70~0.85 |
| 可用版 | 300~500 | 1800~3000 | ≥0.90 |
| 稳健版 | 800+ | 5000+ | ≥0.93 |

> 起步不必等到凑齐几千张。先按 MVP 数量标 3 类（phone / case_bottom / case_top）跑通链路，再补 manual / charger / cable。

### 2.3 多样性矩阵（每个类都要覆盖，否则现场翻车）
- **背景/桌面**：纯色台面、带纹理台面、不同工位
- **姿态/角度**：旋转、平放、斜放、立放
- **尺度**：远近不同（占画面 5%~60%）
- **光照**：上午/下午/开灯/阴天/侧光
- **遮挡（关键）**：被手、手臂、其他物料部分遮挡——作业过程中手必然挡住物料，必须大量包含这种样本，否则推理时一遮挡就漏检
- **类内差异**：不同型号手机、不同颜色盒、不同品牌充电器

### 2.4 负样本
- 空场景、无关物品（水杯、螺丝刀、抹布）→ 减少误检（把这类当背景，不标任何框）

## 3. 标注规范

### 3.1 格式（标准 YOLO txt，每张图一个同名 `.txt`）
每行一个目标：`class_id cx cy w h`（全部归一化到 0~1，相对图像宽高）

```
0 0.452 0.521 0.120 0.180   # phone
2 0.500 0.550 0.200 0.150   # case_bottom
```

### 3.2 边界框规则
- **紧贴物体外缘**，留出 2~5px 余量即可，不要框太大。
- **手遮挡时**：框物体「可见部分的最小外接矩形」即可（YOLO 学的是外观，部分遮挡样本反而提升鲁棒性）。
- **部分出框**：只标画面内可见部分。
- **小物体（cable）**：只要占 ≥10px 就标；极小的可暂不标（YOLO 小目标 recall 本就低，靠增强弥补）。
- **一个物体一个框**，不要把叠在一起的多个物料合并成一个框。

### 3.3 难例处理
- **重叠**：分别框，允许框重叠。
- **透明/反光盒**：按可见轮廓框，不要框玻璃反光高光区。

## 4. 目录结构（YOLOv8 标准）

```
datasets/sop_phone_det/
├── images/
│   ├── train/   *.jpg
│   └── val/     *.jpg
├── labels/
│   ├── train/   *.txt   （与 images/train 同名）
│   └── val/     *.txt
└── data.yaml
```
> 建议 train:val = 8:2 随机切分；同一工位/同一次录制的一组图不要同时进 train 和 val（防止信息泄露）。

## 6. 标注工具
- **LabelImg**（本地轻量，适合单人快速标）—— 推荐起步用。
- **CVAT / Roboflow**（网页协作、支持自动预标）—— 多人或量大时用。
- **提效技巧**：先用现有 COCO `yolov8s.onnx` 在你的图上跑一遍，把能认出的（手机、近似盒）当预标，人工只补 `case_top/bottom/manual/charger/cable` 并修正错误框，效率翻倍。

---

## 7. 数据增强（训练时）
- YOLOv8 默认已开：`mosaic=1.0`、`mixup`、`hsv`、`flip`、`scale`、`translate`、`copy-paste`。
- **针对 `cable` 小物体**：可把 `imgsz` 提到 960 提升小目标 recall；或加大 `copy-paste` 让小物体多次出现。
- 训练最后 10~20 轮可关掉 `mosaic`（设置 `close_mosaic=10`），稳定收敛。

---

## 8. 训练与导出（一键脚本见 `scripts/train_sop_detector.py`）

```bash
pip install ultralytics        # 在训练机执行，需 CUDA 环境
python scripts/train_sop_detector.py \
    --data configs/sop/sop_phone_detector_data.yaml \
    --model yolov8s.pt --epochs 200 --imgsz 640 --batch 16
```
脚本会自动：① 训练 → ② 导出 `best.onnx` → ③ 复制到 `yolo_models/sop_phone_yolov8s.onnx`。

---

## 9. 验收指标
- **mAP50 ≥ 0.90**，且 6 类 AP 均衡（`cable` / `charger` 不低于 0.85）。
- **现场实测**：在真机画面连续跑 100 帧，统计漏检（该框没出）/ 误检（出无关框）次数。
- **部署**：把 `sop_*.yaml` 的 `model.path` 指向 `yolo_models/sop_phone_yolov8s.onnx`，`model.classes` 改为这 6 个英文名。

---

## 10. 分阶段交付建议
1. **P1（1~2 天）**：标 `phone` + `case_bottom` + `case_top` 各 100~150 张 → 训练初版 → 验证 `object_present`（下盖里有没有手机）。
2. **P2（2~3 天）**：补 `manual` / `charger` / `cable` → 完整 6 类 → 验证 `hand_near_object`（手是否靠近充电器/线）。
3. **P3（持续）**：把现场误检/漏检的截图回流进数据集，迭代 2~3 轮，mAP 稳定 ≥0.93。
