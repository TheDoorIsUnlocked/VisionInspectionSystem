## DWPose 测试：手部只显示 5 个点的问题修复

用户运行时反馈：启用 DWPose 后，画面上手部只显示 5 个红点。

### 根因

问题不在 DWPose 检测层，而在 **UI 绘制层故意过滤**。`src/UI/VisionInspection.UI/ViewModels/MainViewModel.cs` 中：
- `DrawHandPoses()` 注释写死 "只显示指尖关键点，减少视觉干扰"，仅绘制 `ThumbTip/IndexFingerTip/MiddleFingerTip/RingFingerTip/PinkyTip` 5 个指尖。
- `DrawHandSkeleton()` 只画手腕到 5 个指尖的 5 根直线，未使用 `HandSkeletonConnections.Connections`。

因此 DWPose 很可能已返回 21 点，只是 UI 只画了 5 个。

### 修复

修改 `MainViewModel.cs`：
1. `DrawHandPoses()` 改为绘制全部 21 个关键点：
   - 手腕青色（半径 8）
   - 指尖红色（半径 7，带白色描边和标签）
   - 其余关节黄色（半径 5）
   - 仍用 `SkeletonConfidenceThreshold`（默认 0.1）过滤低置信度点
2. `DrawHandSkeleton()` 改为遍历 `HandSkeletonConnections.Connections` 绘制完整骨架。
3. 新增诊断输出：`System.Diagnostics.Debug.WriteLine` 每手打印总点数、有效点数、平均置信度，便于在 IDE 输出/即时窗口确认 DWPose 实际输出。

## DWPose 是否真正在跑的核实（用户确认开发机本机运行）

用户质疑"现在用的是不是 DWPose 模型"。经确认：测试程序运行在**开发机本机**，硬编码路径 `e:\yolo\YoloDotNet-master\DWPose-onnx\models` 存在且包含两个 ONNX 模型。

### 源码链路核实

- `sop_config.json`：`"HandDetectionBackend": "DWPose"`
- `SOPModule.InitializeHandPoseEstimationAsync`：`Backend == DWPose` → `new DWPoseHandEstimationService()`
- `DWPoseHandEstimationService.InitializeAsync` → `new DWPoseHandDetector("...yolox_l.onnx", "...dw-ll_ucoco_384.onnx")`
- `DWPoseHandDetector` 初始化失败时 `SOPModule` 会 catch 并把 `_handPoseService` 置 null → **如果失败就不会看到任何手部点**。

### 独立模型验证（Python）

在隔离 venv 中安装 `onnxruntime` + `opencv-python-headless`，运行 `scripts/dwpose_hand_inference.py`：

```
[OK] 模型已加载 | det=yolox_l.onnx pose=dw-ll_ucoco_384.onnx | GPU=False
[OK] 结果已保存: /tmp/dwpose_demo2.png
```

输出骨架图显示完整 21 点手部结构，证明两个 ONNX 模型本身正常工作。

### 结论

在开发机本机、使用包含 DWPose 改动的最新构建时，**后端确实是 DWPose**。用户之前看到的 5 个点就是 UI 绘制层过滤（已修复）。

- 根因（双重）：
  1. **`Dispatcher.Invoke` 同步阻塞**：相机回调线程和推理线程都同步等 UI 线程响应，UI 一忙就堆帧。
  2. **推理旧帧覆盖 CurrentImage**：`PerformSOPDetectionAsync` 完成后用 `resultBitmap = sourceBitmap.Copy()` 把"推理开始时的旧帧 + 检测框"写回 `RoiEditorViewModel.CurrentImage`，但此时相机已经又出了 N 帧，导致画面退回上一帧。
- 修复方案（关键改动）：
  - 新增字段 `_lastSopResult` 缓存最近一次 SOP 检测结果（含老化计数器 `_noSopResultFrameCount` / `MaxNoSopResultFrames=15`）。
  - **`OnCameraImageGrabbed`**：每收到一帧新相机画面，用 `_lastSopResult` 在该最新帧上叠加渲染（检测框 + 手部骨架 + 违规），再设给 `CurrentImage`。画面永远是"最新相机帧 + 最新检测结果"。
  - **`PerformSOPDetectionAsync`**：不再覆盖 `RoiEditorViewModel.CurrentImage`，只缓存 `_lastSopResult` 和更新数据字段（状态栏、检测列表、违规）。
  - **`Dispatcher.Invoke` → `BeginInvoke`**：相机帧投递改为异步，不再阻塞相机采集线程。
  - 抽取 `DrawSOPDetectionOverlay(canvas, info, sopResult)` 方法供两处复用，`DrawSOPDetectionResults` 改为调用它。
- 修改文件：
  - `src/UI/VisionInspection.UI/ViewModels/MainViewModel.cs`
- 编译：SOP 模块 + UI 均 0 错误。
- 注意：手部骨架可能比最新帧晚 1-2 帧显示，但视觉上几乎无感，远好于"画面退回上一帧"。


### 修复检测框闪烁/跳动（2026-08-05 23:30）
- 用户反馈："yolo识别到的物体的box标签也是一闪闪的，一点都不丝滑"。
- 根因：`_lastSopResult` 缓存的是整个结果，但每帧 YOLO 独立检测，`Detections` 列表本身抖动——某帧检测到 cell phone(0.93)、下一帧漏检或置信度波动 → 框消失/出现；即使一直在，bbox 每帧跳几像素。**无任何时序平滑/目标跟踪**。
- 方案：新增 `DetectionTrackSmoother`（`src/UI/VisionInspection.UI/Services/DetectionTrackSmoother.cs`），实现：
  1. **IOU 匹配跟踪**：每帧新检测与现有"活跃轨迹"按同 label + IOU 贪心匹配。
  2. **EMA 位置平滑**：匹配上的框 bbox = old*0.65 + new*0.35，位置渐变不跳变。
  3. **确认机制**：新检测需连续命中 `confirmHits=2` 帧才显示，消除单帧噪点闪现。
  4. **保持机制**：轨迹丢失后保持 `maxMissed=4` 帧、位置沿用上一帧、置信度衰减 0.85，消除短暂漏检的闪烁；超过上限才删除。
- 接入点（MainViewModel.cs）：
  - 字段 `_detectionSmoother`。
  - `PerformSOPDetectionAsync` 拿到 sopResult 后 `_detectionSmoother.Update(sopResult.Detections)`（仅推理出新结果时更新）。
  - `DrawSOPDetectionOverlay` 用 `_detectionSmoother.GetActiveBoxes()` 画框，替代原始 `sopResult.Detections`。
  - `StopSOPDetectionAsync` 里 `Clear()` + 清空 `_lastSopResult`。
- 关键设计：Update 只在推理出新结果时调用（非每帧渲染时），渲染时只读 GetActiveBoxes，避免重复更新。
- 参数默认：iouThreshold=0.3, ema=0.35, confirmHits=2, maxMissed=4, missDecay=0.85。
- 编译：UI 项目 0 错误。
- 注意：右侧 DetectionResults 列表仍用原始 detections（未平滑），如需一致可后续改造。

### v9 最后一步 UI 一直"进行中" + 检测完不循环（2026-08-05 23:58）
- **现象**：1-4 步 OK，第 5 步"完成"卡"进行中"；5 步全过之后 SOP 不再循环，相机继续推帧但没有 SOP 日志。
- **根因 1（最后一步 UI 状态）**：`SOPStateMachine.CompleteCurrentStep`（Models/SOPStateMachine.cs:269-278）在 `CurrentStepId >= Steps.Max` 时直接走 Completed 分支 + 触发 `WorkflowCompleted` 事件，**不再触发 `StepChanged` 事件**。而 UI 端 `SOPModuleView.OnSOPStepChanged`（Views/SOPModuleView.xaml.cs:1365）只把事件里的 `CurrentStepId-1` 对应步骤标为 Running，**从未主动把最后一步标为 Completed**。所以最后一步永远停留在 Running="进行中"。
- **根因 2（SOP 不循环）**：
  1. `SopyamlSettings` 类根本**没有** `AutoResetOnComplete` / `ResetDelaySec` 字段——yaml 即使写了这俩 key，反序列化后也不会进 `SOPGlobalSettings`。
  2. `SOPYamlConverter.ParseYaml`（Models/SOPYamlConfig.cs:498-512）硬编码 `AutoResetOnComplete = false, ResetDelaySec = 5`，所以即使模型支持，yaml 没写就永远是 false。
  3. `SOPGlobalSettings.AutoResetOnComplete` 默认 `false`（Models/SOPWorkflow.cs:106）。
  4. 即便 `AutoResetOnComplete = true`，`SOPStateMachine` 调用的 `Task.Delay(...).ContinueWith(_ => Reset())` 只调 Reset，**没重新 Start workflow**；Reset 后状态变 Idle，`ProcessFrame` 第一行 `if (CurrentState != Running) return;` 直接 return，所以 ProcessFrame 永远不做事，日志也会停。
- **修复**：
  1. `SOPModuleView.OnSOPWorkflowCompleted` 加 `SetStepResult(_steps.Count - 1, isPass)`——在 WorkflowCompleted 事件里手动把最后一步 UI 标为 Completed/Failed。
  2. `SopyamlSettings` 加 `auto_reset_on_complete` / `reset_delay_sec` 字段（snake_case alias，默认 true/3）。
  3. `SOPYamlConverter.ParseYaml` 把硬编码 `false/5` 改为 `yamlSop.Settings.AutoResetOnComplete / ResetDelaySec`（用 SopyamlSettings 模型默认值）。
  4. `SOPGlobalSettings.AutoResetOnComplete` 默认改为 `true`，`ResetDelaySec` 改为 `3`（持续监控场景友好）。
  5. `SOPStateMachine.CompleteCurrentStep` AutoResetOnComplete 分支改为 `Reset(); Start(workflow);`——既清空又重启。
  6. yaml 显式加 `auto_reset_on_complete: true` / `reset_delay_sec: 3`（即使不写也会走模型默认值，显式更易运维）。
- **验证**：bin 下 yaml 已带新字段；编译 0 错误；预期行为——5 步全过后所有步骤显示 OK，3 秒后自动重置回步骤 1"等待"，相机继续推帧、日志继续输出。
- **教训**：
  - **状态机最后一步要走"完成事件"路径**而不是"步骤变化"路径，UI 必须在 WorkflowCompleted 里显式收尾最后一步。
  - **循环机制不能只靠延迟 + Reset**，必须 Reset+Start 重新进入 Running 状态，否则 `ProcessFrame` 入口过滤会卡死。
  - **YAML 配置项的默认值要双层一致**——`SopyamlSettings` 模型默认值和 `SOPGlobalSettings` 默认值以及 `ParseYaml` 硬编码值必须一致；否则配了循环也未必生效。
